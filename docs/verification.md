# 산출물 3 — 자료구조 동작 확인 기록

2026-10-23 · Python 3.13.5. 제출 전 별도의 확인 코드에서 자료구조 API를 직접 호출했다. 다음은 실제 표준 출력 원문이다.

```text
가운데 B 삭제 / 앞: A C D
가운데 B 삭제 / 뒤: D C A
C를 맨 앞으로 / 앞: C A D
C를 맨 앞으로 / 뒤: D A C
확장 전: 버킷 8, 키 2, 로드 0.250
충돌 키 aa: 인덱스 0, GET "1"
충돌 키 ai: 인덱스 0, GET "2"
경계: 버킷 8, 키 6, 로드 0.750 → 확장 없음
aa 덮어쓰기: "updated", 키 6, 버킷 8
7번째 키 저장: 7/8 = 0.875 > 0.75 → 버킷 2배 확장
확장 후: 버킷 16, 키 7, 로드 0.4375
확장 후 전체 조회: aa=updated, ai=2, k0=0, k1=1, k2=2, k3=3, k4=4
조회 확인: 7/7 (aa→0, ai→8)
힙 입력: 5 1 9 3 8 / 개수 5 / peek (1, 'v1')
힙에서 꺼낸 우선순위: 1 3 5 8 9
꺼낸 뒤 개수: 0 / 빈 peek·pop: None / 모든 검증 PASS
```

**설계 이유.** 문자마다 `h = (31*h + ord(문자)) & 0xFFFFFFFF`를 계산하고 `h % 버킷수`로 위치를 정했다. 문자 순서를 반영하고 계산 정수의 크기를 제한하기 위해서다. `aa`는 3104, `ai`는 3112여서 버킷 8에서는 둘 다 0이다. 같은 버킷의 이중 연결 리스트에서 키를 직접 비교하므로 두 값이 보존된다. 버킷 16에서는 각각 0과 8로 재배치된다. 새 배열을 모두 채운 뒤 교체하고 키 개수는 바꾸지 않는다.

**시간 복잡도.** n=키 수, m=버킷 수, K=비교하는 키의 최대 길이(최소 1), S=전체 저장 키 길이의 합. 평균은 키가 고르게 분포할 때다.

| 연산 | 평균/상각 | 최악 |
| --- | --- | --- |
| 저장(확장 제외)·조회·삭제 | O(K(1+n/m)) | O(K(n+1)) |
| 새 키 저장(확장 포함) | 고른 분포·길이 상한 K에서 상각 O(K) | O(K(n+1)+m+n+S) |
| 버킷 확장 | O(m + n + S) | O(m + n + S) |
| 모든 키 순회 | O(m + n) | O(m + n) |

노드 참조가 있는 연결 리스트의 삽입·삭제·이동은 O(1), 순회는 O(n)이다. 힙의 조정은 O(log n), peek·길이는 O(1)이다. Python 배열의 push는 상각 O(log n), 단일 재할당 시 O(n)이며 pop도 축소 재할당 시 O(n)일 수 있다. 상세 근거와 파일별 설명은 README에 적었다.

# 찾는 데이터를 바로바로 꺼내 주는 저장소 만들기

과제의 기능 요구 사항과 제약 사항에 맞춰 작성한 Python 메모리 저장소다. 자료구조 3종을 직접 구현하고, 해시맵을 사용하는 명령행 프로그램과 실제 실행 기록을 함께 제공한다. 보너스 과제는 범위에 포함하지 않았다.

## 실행

Python 3.10 이상에서 프로젝트 폴더로 이동해 실행한다. 설치할 외부 패키지는 없다.

```sh
python3 main.py
```

`mini-redis>`에 명령어를 입력한다. `exit` 또는 `quit`으로 종료하며 EOF와 Ctrl+C로도 종료할 수 있다. 종료하면 메모리의 데이터는 사라진다.

## 최종 결과물

```text
.
|-- main.py
|-- linked_list.py
|-- hash_map.py
|-- min_heap.py
|-- README.md
|-- .gitignore
`-- docs/
    |-- run.md               # 산출물 2: 실제 명령행 실행 기록
    `-- verification.md      # 산출물 3: 자료구조 동작 확인 기록
```

산출물 1은 루트의 네 Python 파일이다. 산출물 2는 [실행 기록](docs/run.md), 산출물 3은 [동작 확인 기록](docs/verification.md)이다.

## 명령어와 출력

명령어는 대소문자를 구분하지 않으며 키와 값은 구분한다. 키와 값은 문자열만 저장한다.

| 입력 | 출력 |
| --- | --- |
| `SET key value` | `OK`; 기존 키이면 값만 변경 |
| `GET key` | `"value"`, 없으면 `(nil)` |
| `DEL key` | 삭제하면 `(integer) 1`, 없으면 `(integer) 0` |
| `EXISTS key` | 있으면 `(integer) 1`, 없으면 `(integer) 0` |
| `DBSIZE` | `(integer) N` |
| `KEYS` | `1. "key"` 형식의 각 줄, 비어 있으면 `(empty array)` |

`KEYS`는 인자를 받지 않으며 패턴 검색을 하지 않는다. 출력 순서는 버킷 인덱스와 체인 순회 순서이며, 확장 후에는 달라질 수 있다. 큰따옴표로 감싼 공백 포함 값과 빈 문자열도 지원한다.

```text
SET place "New York"
SET empty ""
```

표준 라이브러리 `shlex.split`으로 문자열을 파싱하므로 작은따옴표와 백슬래시 인용도 사용할 수 있다. 공백 없는 일반 문자열은 인용할 필요가 없다. 출력에서는 큰따옴표·백슬래시·줄바꿈·탭을 이스케이프해 한 줄을 유지한다.

지원하지 않는 명령어와 인자 오류는 아래 두 형식만 사용하며 사용자가 입력한 명령어의 대소문자를 유지한다.

```text
(error) ERR unknown command '<cmd>'
(error) ERR wrong number of arguments for '<cmd>' command
```

닫히지 않은 따옴표는 지원 명령어이면 인자 오류로 처리한다. 빈 줄은 무시한다. `exit extra` 같은 종료 명령의 인자 오류도 동일한 규칙을 따른다. 자료구조 API의 잘못된 타입이나 잘못된 노드 참조에는 Python 예외를 쓰지만, 명령행의 사용자 입력 오류는 위 두 형식으로만 응답한다.

## 파일을 나눈 기준과 API

`linked_list.py`는 노드 연결만, `hash_map.py`는 해시·충돌·재배치만, `min_heap.py`는 우선순위 순서만 맡는다. `main.py`는 입력을 파싱하고 명령을 검사해 자료구조를 호출한 다음 응답을 형식화한다. 자료구조는 출력 형식이나 프롬프트를 알 필요가 없다. 파일을 나누면 구조별로 시험하고 수정할 수 있으며, 한 파일에서 파싱과 포인터 조작이 섞이는 일을 줄일 수 있다.

| 클래스 | 주요 API | 반환/동작 |
| --- | --- | --- |
| `LinkedList` | `append_left(data)`, `append_right(data)` | 삽입한 `Node` 반환 |
| | `pop_left()`, `pop_right()` | 제거한 값 반환; 비어 있으면 `IndexError` |
| | `remove(node)` | 제거한 값 반환 |
| | `move_to_front(node)` | 같은 노드 객체를 맨 앞으로 이동 |
| | `iter_forward()`, `iter_reverse()`, `len(list)` | 앞/뒤 순회와 길이 |
| `HashMap` | `put(key, value)` | 문자열 쌍 저장 또는 갱신 |
| | `get(key)` | 값 또는 `None` |
| | `delete(key)`, `contains(key)` | 성공/존재 여부를 bool로 반환 |
| | `keys()`, `len(map)` | 키 순회와 개수 |
| | `capacity`, `load_factor`, `bucket_index(key)` | 확인 기록용 상태 |
| `MinHeap` | `push(priority, value)` | 우선순위 쌍 삽입 |
| | `peek()`, `pop()` | `(priority, value)` 쌍 또는 빈 경우 `None` |
| | `len(heap)` | 저장된 쌍의 개수 |

힙의 우선순위는 서로 비교 가능한 수를 전제로 한다. 비교에는 우선순위만 사용하므로 동순위일 때 값 자체를 비교하지 않는다. 동순위 반환 순서는 보장하지 않는다. `None`은 해시맵의 미존재 표식이며, 실제 값은 문자열이므로 빈 문자열과도 구분된다.

## 연결 리스트와 체이닝

각 `Node`는 `prev`, `next`, `owner`와 값을 가진다. 가운데 노드를 지울 때 앞 노드의 `next`를 뒤 노드로, 뒤 노드의 `prev`를 앞 노드로 바꾸면 된다. 처음이나 마지막 노드이면 `head`와 `tail`도 바꾼다. 노드 참조가 이미 있으면 탐색 없이 일정한 개수의 참조만 바꾸므로 O(1)이다. 노드 소유자를 확인하는 작업도 O(1)이며, 다른 리스트의 노드나 이미 제거한 노드로 구조를 망가뜨리는 것을 막는다.

`move_to_front`는 새 노드를 만들지 않고 기존 노드를 분리해 `head` 앞에 다시 연결한다. 길이와 노드 객체의 정체성은 유지한다. 양방향 순회는 서로 역순이어야 한다.

해시맵 버킷에는 이 연결 리스트를 재사용한다. 각 노드는 `(key, value)` 쌍을 저장한다. 같은 버킷에 여러 키가 들어와도 각 노드를 직접 비교하므로 충돌한 키를 모두 찾을 수 있다. `delete`는 키를 찾는 비용이 들지만, 찾은 다음의 노드 제거는 O(1)이다. 이중 연결 리스트를 재사용해 중복 구현을 줄였고, 대신 단일 연결 리스트보다 노드당 참조 메모리를 더 사용한다.

## 해시 함수 설계 이유

키의 문자를 왼쪽부터 읽으며 다음과 같이 계산한다.

```text
h = 0
각 문자 c에 대해 h = (31 * h + ord(c)) & 0xFFFFFFFF
인덱스 = h % 버킷수
```

31을 곱한 뒤 문자를 더해 문자 순서가 결과에 영향을 주게 했다. 단순 문자 코드 합은 `ab`와 `ba`를 구분하지 못하지만 이 계산은 누적 순서를 반영한다. 매 단계 32비트로 제한해 긴 문자열에서 정수 자체의 크기가 계속 커지는 일을 막는다. `ord`를 사용하므로 한글이나 이모지도 같은 절차로 처리한다. Python 내장 해시를 쓰지 않아 실행을 다시 해도 인덱스를 재현할 수 있다.

이 방식도 충돌을 없애지는 못한다. 특히 2의 거듭제곱 버킷 수와 문자 규칙에 따라 편향이 생길 수 있다. 학습용으로 단계별 계산을 설명할 수 있는 방식을 선택했고, 최악의 충돌에서는 선형 탐색이 된다는 한계를 문서화했다.

실제 기록의 `aa`는 `97*31+97=3104`, `ai`는 `97*31+105=3112`다. 버킷 8에서는 모두 0이지만 버킷 16에서는 각각 0과 8이다. 계산 방식을 `h=33*h+ord(c)`로 바꾸면 `aa`는 3298, `ai`는 3306으로 버킷 8에서 여전히 같은 2번 버킷이다. 반대로 현재 누적값의 상위 비트를 섞는 `h ^ (h >> 3)`을 마지막에 적용하면 같은 버킷 수 8에서도 각각 4와 5로 갈라진다. 두 키가 계속 충돌하는지는 함수와 버킷 수를 함께 계산해야 판단할 수 있다.

## 버킷 확장

초기 버킷은 8개다. 신규 키를 저장한 직후 `키수 * 4 > 버킷수 * 3`이면 버킷 수를 정확히 2배로 늘린다. 나눗셈 대신 정수 비교를 써 0.75 경계의 반올림 문제를 피한다. 6/8이면 확장하지 않고, 7번째 키 저장 후 7/8이면 확장한다. 기존 키의 값을 갱신할 때는 키 수를 늘리지 않는다.

확장할 때 새 버킷 배열을 미리 만들고 모든 기존 노드의 키와 값을 읽어 새 인덱스로 복사한다. 모든 복사가 끝난 뒤에만 배열 참조를 바꾼다. 기존 배열을 순회 중에 고치지 않고, 일반 저장 메서드를 재호출하지도 않아 중복 집계나 중첩 확장을 피한다. 키 개수는 그대로 유지한다.

처음부터 크게 잡으면 확장 빈도와 충돌을 줄일 여지가 있지만 빈 배열 메모리와 모든 버킷을 훑는 `KEYS` 비용이 커진다. 작게 시작하고 필요할 때 늘리면 초기 메모리를 아끼지만 확장 순간에는 전체 키를 다시 읽는 지연과 구·신 배열의 일시적 공존 비용이 생긴다.

## 최소 힙

배열 위치 i의 부모는 `(i-1)//2`, 자식은 `2*i+1`, `2*i+2`다. 삽입은 배열 끝에 추가한 뒤 부모보다 작은 동안 위로 올린다. 꺼내기는 루트를 반환하고 마지막 쌍을 루트로 옮긴 뒤 두 자식 중 더 작은 쪽과 비교해 아래로 내린다. 나머지 부분의 힙 순서는 바꾸지 않으며, 루트까지 또는 잎까지 한 경로만 고친다. 루트가 항상 최솟값이므로 전부 꺼내면 우선순위 오름차순이다.

## 시간·공간 복잡도와 해석

n은 키 수, m은 버킷 수, K는 해당 연산에서 비교하는 키들의 최대 길이(최소 1), S는 전체 저장 키 길이의 합이다. 평균은 키가 고르게 분포한다는 가정이며 보장은 아니다. 문자열 비교도 최악 O(K)로 계산했다.

| 연산 | 평균 또는 상각 | 최악 |
| --- | --- | --- |
| 저장(확장 제외)·조회·삭제 | O(K(1+n/m)) | O(K(n+1)) |
| 신규 저장(확장 포함) | 고른 분포·키 길이 상한 K에서 상각 O(K) | O(K(n+1)+m+n+S) |
| 버킷 확장 | O(m+n+S) | O(m+n+S) |
| 모든 키 순회 | O(m+n) | O(m+n) |
| 연결 리스트 삽입·제거·이동(노드 참조 보유) | O(1) | O(1) |
| 연결 리스트 순회 | O(n) | O(n) |
| 힙의 상향/하향 조정 | O(log n) | O(log n) |
| 힙 push/pop(배열 재할당 포함) | 상각 O(log n) | O(n) |
| 힙 peek·각 자료구조 길이 | O(1) | O(1) |

키 길이가 제한되어 있고 고르게 분포하면 해시맵의 저장·조회·삭제는 평균 O(1), 확장은 O(n+m)이다. 이중으로 늘리는 배열에서 전체 재배치 횟수의 합은 등비급수이므로 신규 저장은 평균적으로 상각 O(1)이다. 단일 저장의 확장 지연은 여전히 선형이며, 충돌이 몰리면 확장이 없어도 체인 탐색은 선형이다. `KEYS`는 분포가 좋아도 전체 버킷과 키를 읽어야 한다. 명령행의 문자열 응답을 만드는 시간과 메모리는 출력 길이도 더해야 한다.

힙은 실제 Python 리스트를 쓰므로 노드 교환 경로가 O(log n)이어도 배열 메모리를 늘리거나 줄이는 한 번의 연산은 O(n)이 될 수 있다. 연결 리스트는 동적 배열로 저장하지 않아 해당 재할당 비용이 없다.

저장소의 공간은 노드·버킷 O(n+m)에 문자열 전체 크기를 더한 정도이고, 확장 중에는 새 배열·노드가 추가로 필요하다. 힙과 연결 리스트는 항목 수에 비례하는 공간을 쓴다.

## 제약 준수와 검증

네 구현 파일에 금지된 컨테이너·내장 해시·키 멤버십 연산을 사용하지 않았다. 버킷은 고정 길이 배열로 초기화하고 인덱스와 길이만 사용하며, 재배치에서도 인덱스를 직접 순회한다. `append`/끝의 `pop`은 힙과 출력용 목록에만 사용한다. 키 조회는 체인의 키를 직접 비교한다. 통신·영속성·TTL·메모리 제한·동시성은 구현하지 않았다. `shlex`는 입력 문자열 파싱만 담당한다.

제출 전 별도의 검증 환경에서 Python 3.13.5로 18개 테스트를 통과했다. 연결 리스트 1,000회, 해시맵 3,000회, 힙 2,000회의 고정 시드 무작위 연산으로 각 단계의 길이·값·연결·힙 순서도 확인했다. 금지된 문법/호출은 AST 검사로, 버킷 배열의 접근 방식은 소스 검토로 확인했다. Python 3.10 호환 문법으로 작성했으며 실행 검증 환경은 3.13.5다.

이 코드와 설계 설명은 사용자 요청으로 AI가 작성했다. 실행 기록과 테스트 결과는 작업 환경에서 실제 실행해 얻었다.
